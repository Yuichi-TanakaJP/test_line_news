# youtube-stocks — 株YouTube文字起こし → 銘柄+見立て抽出 → message.txt 生成

株取引YouTube動画の文字起こしから、**言及された銘柄と配信者の見立て**を抽出して
LINE送信用の本文を `message.txt` に生成する。

前提: 文字起こしは**呼び出し側スクリプトが事前に取得**し、`transcript.txt`
(プロフィールの `transcript_file`) に保存済みである。このスキルは取得は行わない。

以下を厳密に実行する。

1. 設定ファイルを読む。呼び出し時に設定パスが指定されていればそれを、なければ
   `configs/youtube_stocks.json` を読む(複数チャンネルを別プロフィールで運用するため。
   例: `configs/youtube_stocks_kamioka.json`)。その `extraction` / `sections` /
   `rules` / `format` / `title` / `transcript_file` / `output_file` に従う。
   設定に `emphasis`(トップレベル)があれば、その方針を全体の重点として最優先で従う
   (例: ニュース解説を主軸にし、雑談・宣伝は一言に圧縮する 等)。
2. `transcript_file`(既定 `transcript.txt`) を読む。**これだけを情報源**とする。
   ファイルが無い／空の場合は、その旨だけを書いた短い本文を `output_file` に生成して終了する
   (Web検索や憶測で銘柄を補わない)。
2.5 設定に `video_types` があれば**動画種別を判定する**。文字起こし冒頭などの発言から
   各種別の `signals` に照らして判定し、その `emphasis` に従う。判定した種別の `label` を
   タイトル行の先頭に `[ラベル]` として付ける。どちらとも言えなければ網羅(個別銘柄中心)とする。
   `video_types` が無い設定では種別ラベルは付けず、`sections`(と `emphasis` があればそれ)に
   従ってまとめる。
3. 文字起こしから銘柄と見立てを抽出する。**rules を厳守**:
   - 雑談・宣伝(家族・スパチャ反応・視聴者の利益/億トレ報告・チャンネル宣伝など)の扱いは
     **設定の `rules`/`emphasis` に従う**。既定は除外して銘柄と相場の見立てだけを拾うが、
     設定で「話題名だけ一言にまとめる」等の指定があればそれに従う。
   - 自動字幕の固有名詞の誤変換を**文脈から補正**する
     (例『太陽油電/太陽遊電』→太陽誘電、『村谷』→村田製作所、『バダナム子』→バンダイナムコ)。
   - **口頭の証券コードは信用しない**。銘柄名から正式コードを判断し、確信が持てなければ
     コードを「要確認」とし、最後の「注意・要確認」セクションにも挙げる。
   - 各銘柄を `extraction.view_labels` のいずれかで分類し、日本株か米国株かで振り分ける。
   - **根拠はできるだけ情報量を多く**する。配信者が触れた要素を可能な限り盛り込む:
     具体的な数値(株価/騰落率/信用倍率/フィボ水準)、テクニカル指標名(移動平均/ボリンジャー
     バンド/MACD/RSI/ゴールデンクロス)、需給(信用買い残・空売り・期日)、ファンダ材料、
     時間軸(当日/週明け/来月)、配信者の言い回し・ニュアンス。根拠は1〜3行に増えてよい。
   - 同じ銘柄への複数言及は1つにまとめる。最大 `extraction.max_stocks` 件。
   - **事実(配信者がこう言った)と主観的見立てを分け**、中立にまとめる(投資助言にしない)。
4. `format` と `sections` に従い、人間が読みやすい日本語テキストで本文を作る。
   - `video_types` があれば**判定した種別の `emphasis` に従って重点を変える**
     (定期/全体なら個別は主要なものに絞りサマリー・マクロを厚く、ライブ/個別なら網羅的に)。
   - 1行目は `title`(種別を判定した場合は後ろに `[ラベル]` を付ける。例 `... 🦉📺 [定期/全体]`)。
     2行目に動画タイトル(分かれば)と配信日。
   - 各セクションは見出し行 `format.section_header_prefix + "N. セクション名"` で始める。
   - 銘柄は「銘柄名(コード) 見立て」を1行目に、根拠を続く行に詳しく書く
     (根拠は情報量重視。他セクションは簡潔に)。
   - 全体 `format.max_chars` 文字以内。末尾に `format.footer` を入れる。
5. 完成した本文を **`output_file`(既定 `message.txt`)に上書き保存**する
   (このファイルのみを書く)。送信はしない(送信は呼び出し側 `line_news.line` が行う)。

出力は `output_file` のみ。余計な説明や他ファイルの変更はしないこと。
