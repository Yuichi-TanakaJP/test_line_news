test_line_news 機能仕様まとめ

このリポジトリは、毎日の市場ニュース、株式系YouTube動画の内容、株主優待の変更情報を自動で要約・検知し、 LINEに短いメモとして届けるためのローカル運用ツールです。ユーザーは「どんな情報を集めたいか」を設定しておけば、 ツールがニュース調査、YouTube字幕の取得、優待イベント検知、本文作成、LINE送信までを一連の流れで実行します。

最終更新: 2026-06-20

1. ユーザーレベルで提供する機能

このツールの利用者が受け取るものは、大きく3種類です。その日の市場ニュースをまとめたメモ、 株式系YouTube動画で話された銘柄や相場観を整理したメモ、そして株主優待の変更を検知した通知です。 いずれも最終的にはLINEのテキストメッセージとして届きます。

news毎日の市場ニュースをLINEで受け取る

その日に起きた日本株や為替、金利、AI・半導体関連のニュースを調べ、 重要なポイントだけをLINEで読める長さにまとめます。朝刊やニュースサイトを一つずつ追わなくても、 投資や市場チェックに必要な材料を短時間で確認できます。

主な内容

  • 日本株、為替、金利、原油、AI・半導体、個別材料などをまとめる
  • 信頼しやすい公式発表や主要メディアを優先して参照する
  • 実行日JSTと前営業日のニュースを中心に採用する
  • 標準設定では毎日20:00 JSTに自動実行され、LINEへ送信される
技術メモ: 標準プロフィール market の設定を読み、news スキルが本文を作成します。

youtube-stocks株式YouTubeの要点をLINEで受け取る

株式系YouTube動画の字幕を読み取り、動画内で触れられた銘柄、配信者の見立て、 その根拠を抜き出して整理します。長い動画を全部見返さなくても、 どの銘柄について何が話されたかを短時間で把握できます。

主な内容

  • 動画URLを指定して手動で処理できる
  • 登録したYouTubeチャンネルの新着動画を自動で検知できる
  • 一度送信した動画は記録されるため、同じ動画を重複送信しにくい
  • チャンネルごとに別プロフィール・別タスクで独立監視できる（Sho's 08:00/20:00、上岡 11:30、ビタセン 20:30 JST）
技術メモ: YouTube RSSで新着を確認し、字幕ファイルを作ったうえで youtube-stocks スキルがLINE向けの本文に変換します。プロフィール（configs/youtube_stocks*.json）ごとに 字幕・出力・状態ファイルを分けて衝突を防ぎます。

disclosure-events株主優待の変更をLINEで受け取る

全銘柄の株主優待の新設・拡充・変更・廃止などをAPIから検知し、未通知のイベントだけをLINEに届けます。 優待の新設や改悪を見逃さず、対象カードを確認するURL付きで把握できます。

主な内容

  • audience=all の優待 新設・拡充・変更・廃止・要確認 を対象にする
  • 各イベントにmini-toolsの対象カードへ移動する確認URLを付ける
  • 送信成功したイベントだけ記録し、新着がなければ送信しない
  • ランナーが2時間以内の多重起動をロックで回避する
技術メモ: line_news.disclosure がAPIから未通知イベントを取得・整形・送信し、 run_disclosure_events.ps1 が定期実行とログ管理を担います。

4. 通信フロー

ニュースメモ配信

1. ユーザーまたはWindowsタスクが run_market_news.ps1 [profile] を起動する。
2. ランナーが claude -p "/news <profile>" をheadless実行する。
3. news スキルが設定ファイルを読み、WebSearch / WebFetchで最新ニュースを調査する。
4. スキルがLINE向け本文を message.txt に上書き保存する。
5. line_news.line が .env の認証情報を読み、LINE Messaging APIへpush送信する。
6. 実行結果とエラーは logs/ に記録される。

YouTube銘柄メモ配信

1. 手動実行では run_youtube_stocks.ps1 <動画URL>、自動実行では run_youtube_watch.ps1 を起動する。
2. 自動実行時は line_news.watch --list がYouTube RSSから未処理IDを取得する。
3. line_news.transcript が字幕を取得し、transcript.txt に保存する。
4. claude -p が youtube-stocks スキルを実行し、字幕だけを根拠に message.txt を生成する。
5. line_news.line がLINEへ送信する。
6. 送信成功時のみ line_news.watch --mark <videoId> で処理済みに記録する。

6. 主要仕様

領域 仕様
共通出力 message.txt にLINE送信用テキストを上書き保存する。送信本文はLINEテキストメッセージ上限に合わせて最大5000文字を想定。
LINE送信 LINE_CHANNEL_ACCESS_TOKEN と LINE_USER_ID を環境変数または .env から読む。HTTP失敗時はステータスとレスポンス本文を出して終了コード1。
ニュース鮮度 原則として実行日JSTと前営業日の発生分を採用。max_age_hours は36時間、exclude_if_older_than_hours は72時間。古いニュースは本日の新展開がある場合のみ採用可。
ニュース出典 一次情報、日銀、FRB、JPX、TDnet、EDINET、主要企業ブログ、Reuters、Bloomberg等を優先。出典URLが取れない情報は使わない。
YouTube字幕取得 youtube-transcript-api で日本語、英語の順に取得を試みる。字幕がない、動画が無効、取得ブロック時はエラー終了。
YouTube抽出 情報源は字幕ファイルのみ。外部検索で銘柄や株価を補わない。同じ銘柄は統合し、プロフィールの extraction.max_stocks（30〜40件）まで抽出。
動画種別判定 文字起こし冒頭の発言から 定期/全体 または ライブ/個別 を判定し、出力重点を切り替える。判定不能時はライブ扱い。
新着監視 YouTube RSSを利用し、APIキーやYouTube Data APIクォータは不要。1回の処理上限は watch.max_new_per_run、標準3件。チャンネルごとに別プロフィール（別 config・別 state_file・別タスク）で独立監視する。
優待イベント検知 audience=all の優待 新設・拡充・変更・廃止・要確認 をAPIから取得。各イベントに確認URLを付与し、送信成功分のみ processed_disclosure_events.json に記録。新着がなければ送信しない。
ログ PowerShellランナーは logs/ にタイムスタンプ付きログを保存し、30日より古いログを削除する。

7. 制約・注意点

  • LLM依存: 本文生成と抽出は claude -p とスキル指示に依存するため、LLM利用制限や失敗時は送信まで進まない。
  • 外部ネットワーク依存: ニュース調査、YouTube RSS、字幕取得、LINE送信はいずれもネットワーク接続が必要。
  • YouTube字幕: ライブ配信は字幕生成が遅れる、または字幕が存在しないことがある。データセンターIPでは字幕取得がブロックされる場合がある。
  • 自動字幕の誤認識: 銘柄名や証券コードは誤変換されることがある。確信が持てないコードは「要確認」として扱う。
  • 投資助言ではない: ニュースメモとYouTube銘柄メモは情報整理であり、売買判断や投資助言を目的にしない。
  • 二重送信対策: YouTube自動監視はロックファイルで多重起動を避け、送信成功した動画だけ処理済みに記録する。
  • 秘密情報: .env にはLINE認証情報を置くためコミットしない。テンプレートは .env.example。
